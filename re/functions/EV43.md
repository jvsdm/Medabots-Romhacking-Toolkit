## 1. Correção de base (corrige EF.md §1, README "EF", DC5)

- O literal de pool 0x08053184 (e 0x0805319C, 0x080531C0, 0x080531DC, ...) = **0x030057D8**, mas esse endereço NÃO é o
  array: o Ghidra usa `*lit_EventFlagArrayBase_*`, ou seja, 0x030057D8 é uma VARIÁVEL de ponteiro.
- O conteúdo de 0x030057D8 (dump de savestate/replay) = `E0 57 00 03` = **0x030057E0** (bloco E).
- Logo: **array de flags = E = 0x030057E0**, índice k = (id & 0xFFF) >> 1, byte = E + k. Id par: flag bit 0x80,
  campo bits 4-6; id ímpar: flag bit 0x08, campo bits 0-2.
- Consequência: os ids 0..15 (k = 0..7) ficam em E+0..E+7, dentro do que o save copia (E..E+0xCBF). A "lacuna" de
  SV2/EF.md (ids 0..15 não salvos) está ERRADA.

## 2. Id 43 e o 0x13 do ev 185 (New Game)

- Ids removidos pelo 0x13 (`Event_Op13_RemoveEventPermanently` 0x0804BBF4 -> set 0x080531A0), por log de runtime
  (rec_ng, frames 1-4): r0 = 0x7B (123), 0x29 (41), 0x115 (277), 0x2B (43). O id 15 foi setado no quadro 0 (antes do
  primeiro log). Bytes do ev 185 na ROM (arquivo 0x781EC1, endereço 0x08781EC1) = `13 00 0F 13 00 7B 13 00 29 ...`:
  o porte já tem esses ids. Os ids 31/139/57/293/59/201 do log "live" (QA/live_diff) NÃO são removidos pelo 185 nesta run.
- **43 = E+21 = 0x030057F5, bit 0x08.** Dump (0x030057D8 + 29 = 0x030057F5): 00 antes do quadro 4, 08 depois.
  Nenhum 0x12 nem clear (0x08053168) foi chamado em rec_ng de 0 a 3400 quadros: o 43 continua removido.
- Savestate do usuário (ss1, cap. 9): E+21 bit 0x08 = 1 (removido), E+7 (id 15) = 1, E+20 (id 41) = 1.
  newgame.ss0 e rec_ng/start.ss0 (cap. 0, mapa 23): tudo 0.
- Resposta à pergunta (c) do Opus: o 0x13 do ev 185 **grava o bit de removido do 43** (não outro bit).
